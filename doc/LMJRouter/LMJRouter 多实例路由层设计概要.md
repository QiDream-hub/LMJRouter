# LMJRouter 多实例路由层设计概要

## 1. 设计目标

### 1.1 核心目标
构建一个轻量级路由层，将多个独立的 LMJCore 实例（每个实例对应一个独立的 LMDB 环境）整合为统一的逻辑存储系统，实现**写能力的水平扩展**，突破单 LMDB 环境的“单写者”限制。

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| **简单性** | 路由层只做路由，不做分布式事务、不做跨实例查询 |
| **零开销抽象** | 路由决策应在常数时间内完成，不引入显著性能损耗 |
| **语义透明** | 每个实例内部完全保留 LMDB 的 ACID、MVCC 等语义 |
| **渐进复杂度** | 用户可以从单实例简单使用，逐步过渡到多实例高级场景 |

---

## 2. 核心概念

### 2.1 实体指针
每个实体（对象或数组）由**固定长度的全局唯一指针**标识。指针结构划分为：
- **类型标识**：标识实体基础类型（如对象、数组）
- **实例标识**：标识该实体所属的存储实例
- **唯一标识**：实例内唯一的标识符

指针一旦生成，其包含的实例标识**不可变更**。

### 2.2 存储实例
每个存储实例对应一个独立的 LMJCore 环境，包含：
- 独立的 LMDB 环境
- 独立的物理文件存储
- 独立的写锁（从而支持并发写入）

实例之间**物理隔离**，数据不共享，事务不交叉。

### 2.3 路由表
系统维护一个**实例标识到存储实例的映射关系**。该映射：
- 在系统初始化时建立
- 运行时只读（不动态变更）
- 支持通过实例标识常数时间（O(1)）定位目标实例

---

## 3. 事务模型

### 3.1 事务的实例亲和性
每个事务**必须且只能绑定到一个存储实例**。事务创建时需指定其所属的实例标识。

### 3.2 事务类型

| 事务类型     | 创建方式              | 生命周期          | 适用场景           |
| -------- | ----------------- | ------------- | -------------- |
| **自动事务** | 由操作API在无事务参数时自动创建 | 单操作内（自动提交/回滚） | 简单单操作，无需跨操作原子性 |
| **手动事务** | 由用户显式创建，指定实例标识    | 用户控制（显式提交/回滚） | 需要原子性多操作的复杂场景  |

### 3.3 事务路由规则
- **自动事务**：根据操作指针中的实例标识，路由到对应实例，创建临时事务，执行操作后自动结束
- **手动事务**：创建时固定实例标识，后续所有操作必须使用属于同一实例的指针，否则拒绝执行

### 3.4 重要限制
**路由层不提供跨实例事务保证**。若应用需要原子性更新多个实例的数据，必须在应用层实现（如 Saga 模式、TCC 等）。

---

## 4. 操作路由流程

### 4.1 自动事务模式
```
用户调用操作API（无事务参数）
    ↓
解析操作指针，提取实例标识
    ↓
通过路由表查找对应的存储实例
    ↓
在目标实例创建临时事务
    ↓
执行实际数据操作
    ↓
操作成功 → 提交临时事务
操作失败 → 回滚临时事务
    ↓
返回操作结果
```

### 4.2 手动事务模式
```
用户创建事务（指定实例标识）
    ↓
用户调用操作API（传入事务句柄）
    ↓
解析操作指针，提取实例标识
    ↓
检查是否与事务绑定的实例标识一致
    ↓
一致 → 继续执行
不一致 → 返回实例不匹配错误
    ↓
执行实际数据操作
    ↓
用户显式提交或回滚事务
```

## 5. 扩展能力分析

### 5.1 写并发扩展
假设单实例写吞吐量为 T，实例数为 N，且数据分布均匀：
- **理论最大写吞吐量**：N × T
- **实际限制因素**：CPU核心数、磁盘 IOPS、网络带宽等物理资源

### 5.2 读并发扩展
读操作天然受益于：
- 分散到不同实例，减少单实例负载
- 每个实例内部仍保持 LMDB 的高并发读能力

### 5.3 存储容量扩展
总容量 ≈ N × 单实例最大容量（由 map_size 决定）

### 5.4 故障隔离
单个实例的故障不影响其他实例的正常运行

## 6. 设计边界与取舍

### 6.1 明确不支持的特性

| 特性 | 不支持原因 | 替代方案 |
|------|----------|---------|
| **跨实例事务** | 超出路由层职责，引入分布式事务复杂度 | 应用层实现 Saga、TCC 等 |
| **跨实例查询** | 无法在常数时间内完成 | 应用层聚合、建立全局索引 |
| **动态数据迁移** | 指针编码实例标识后不可变 | 初始合理分片、应用层双写迁移 |

### 6.2 设计取舍

| 取舍点 | 选择 | 理由 |
|-------|------|------|
| 实例标识位数 | 固定（如8位） | 简化路由实现，O(1)索引 |
| 路由表动态性 | 只读不动态变更 | 避免锁竞争，保证性能 |
| 指针可变性 | 不可变 | 保证指针可作为永久引用 |
| 跨实例操作 | 禁止 | 保持语义简单，避免错误 |

## 7. 典型应用场景

### 7.1 SaaS 多租户系统
- 每个租户对应一个独立实例
- 指针中包含租户标识
- 租户数据物理隔离，互不影响
- 租户级备份恢复成为可能

### 7.2 时序数据分片
- 按时间范围（如月份）分片
- 每个时间片对应一个实例
- 写入并行进行，历史数据可单独归档
- 查询范围明确，只涉及相关实例

### 7.3 微服务数据分片
- 每个微服务拥有自己的实例
- 服务间通过 API 通信，不共享数据库事务
- 服务可独立扩展、独立部署

### 7.4 用户数据分片
- 按用户 ID 哈希分片
- 每个用户的数据集中在同一实例
- 用户级操作天然具有实例亲和性
- 用户量增长可通过增加实例线性扩展

## 8. 实施建议

### 8.1 实例标识位数选择
- **8位**：最多256实例，适合大多数场景，唯一ID空间大
- **16位**：最多65536实例，适合超大规模部署，唯一ID空间缩小
- 建议通过编译时宏配置，同一系统内保持一致

### 8.2 数据分布策略
- **哈希分片**：根据 key 哈希决定实例，分布均匀
- **范围分片**：按 ID 范围分配，范围查询友好
- **显式指定**：应用层直接控制，最灵活
- **租户绑定**：SaaS 场景自然映射

### 8.3 指针生成器封装
建议提供不同策略的指针生成器实现：
- 哈希分片生成器
- 范围分片生成器
- 租户绑定生成器
- 自定义回调接口

### 8.4 应用层跨实例事务模式
对于需要跨实例一致性的场景，可提供：
- Saga 模式协调器示例
- TCC 事务模板
- 消息驱动最终一致性方案

---

## 9. 总结

本路由层设计通过**指针嵌入实例标识**和**固定路由表**，实现了：

1. **写能力的水平扩展**：突破单 LMDB 环境的单写者限制
2. **零开销路由**：常数时间决策，不引入显著性能损耗
3. **语义保持**：每个实例内部完全保留 LMDB 的 ACID 特性
4. **边界清晰**：明确不支持跨实例事务等复杂特性，保持简单

该设计为需要**线性扩展写能力**且**可接受最终一致性**的应用提供了一个务实、高效的解决方案，同时为上层应用保留了充分的扩展空间。
